## Official report lifecycle

### Server generation

`official_report_artifact.v1` is generated only after exact owner/controller
reauthorization of an existing `obligation.v2`. The content is derived from:

- the shared no-funds Obligation projection;
- one to 50 persisted Evidence summaries for that exact Obligation;
- the versioned unavailable fee policy; and
- fixed redaction metadata.

The report generator accepts the actual shared Obligation fields:

- `originalPrincipalMinor`;
- `outstandingPrincipalMinor`;
- `totalRepaidMinor`;
- `accruedInterestMinor`;
- `accruedFeesMinor`;
- `outstandingFeesMinor`;
- `originationFeeMinor`; and
- `maturityAt`.

During real-browser preparation, an old-field mismatch was found: the first
implementation used non-schema names such as `principalMinor` and
`outstandingMinor`. That could create a SHA-consistent but syntactically invalid
JSON document containing `undefined`. The generator and fixtures were
corrected to the real `obligation.v2` contract. Unit, PostgreSQL, and downloaded
browser evidence now parse the returned JSON and reject any `undefined`
serialization.

### Content safety

- JSON is canonical and newline-terminated.
- CSV quotes every cell and prefixes formula-leading `=`, `+`, `-`, `@`, tab,
  or carriage-return values with a single quote.
- HTML is not an available format.
- Metadata responses never contain `contentBase64`.
- Retrieval supports only `application/json` and
  `text/csv; charset=utf-8`.
- The browser checks active state, fixed safety flags, base64 shape, safe
  filename, server integrity result, and WebCrypto SHA-256 before download.
- PII, secrets, raw transaction data, browser-authored fields, production
  authority, signed URLs, public links, and bearer access remain false or
  absent.

### Durable lifecycle

Migration `0028_official_report_artifacts` adds:

- forced RLS and Tenant-context guards;
- immutable content, content hash, artifact hash, source binding, controller
  hash, safety flags, and fee-policy fields;
- a maximum one-hour lifetime;
- terminal `active -> revoked` transition only;
- no delete path;
- exact Obligation foreign key;
- bounded abuse capacity;
- production-role grants; and
- reconciliation coverage.

Create is idempotent and persists content while returning metadata only. Read
and retrieve recheck the current active resource relationship. Retrieve also
checks expiry and server SHA-256. Revoke is bound to the server-HMAC reference
of the creator, closes the authorization resource, and is terminal. Missing,
cross-Actor, cross-Tenant, expired, revoked, or otherwise inaccessible reports
remain non-enumerating.

The PostgreSQL suite additionally proves:

- concurrent duplicate create has one durable effect and an exact replay;
- cross-Actor and cross-Tenant retrieval fail closed;
- revocation is durable and replay-safe;
- CSV content and hashes survive process/runtime reconstruction;
- a fresh Gateway retrieves the exact persisted bytes; and
- complete reconciliation remains clean.
